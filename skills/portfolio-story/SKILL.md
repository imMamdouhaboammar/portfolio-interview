# Portfolio Story: factual narrative and localization

Work only from confirmed, publication-approved facts, an existing approved profile and the user's chosen audience, field and register. Read sibling portfolio-interview/references/copy-rules.md, field-playbook.md and profile-schema.md on demand.

## Workflow

1. Identify the reader's hiring or collaboration decision and the proof needed to support it. Keep measurable results only when the ledger identifies a source.
2. Draft three differentiated headline options, a concise summary and the requested case-study text. For each project use context, actual contribution, demonstrable artifact and verified outcome; do not turn team achievements into individual claims.
3. Adapt for English, Arabic MSA, or user-approved dialect. Use proper RTL structure and localized text rather than mechanical translation. Follow the existing banned-copy, no-invented-metrics and testimonial-permission rules.
4. Draft title, meta description and structured-data text as appropriate. Do not create fictional FAQs, reviews or credentials for search visibility.
5. Show changed copy and source-sensitive facts for user approval before applying them to profile.json.

## Neural handoff

Missing evidence -> portfolio-source; unanswered facts or approval -> portfolio-interview; approved messaging -> portfolio-design (new page) or portfolio-build (copy-only update). If portfolio-audit returns copy or factual findings, revise the specific field then rerun affected checks.

Output a copy patch with affected profile.json paths and a separate evidence/approval summary. Never hand-edit generated HTML.
